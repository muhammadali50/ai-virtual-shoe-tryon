A. EXECUTIVE SUMMARY
======================================================================

What the project is
  An "AI Virtual Shoe Try-On" prototype built in steps. Two INDEPENDENT
  tracks exist in the repository and share no code:
    1. frontend/  - a mobile-first React/Vite/TypeScript web app with two pages.
       "/" is the Formal Collection catalog: 15 LOGO formal shoes, each with
       its own swipeable photo gallery, built from data/logo-formal/.
       "/scan/" is the "Step 5" foot scan prototype. It shows a rear-camera preview. With Scan Foot, the user taps
       one foot, the app freezes that frame, and an on-device
       MediaPipe MagicTouch interactive-segmentation model highlights a
       "segmentation candidate" region in green. Everything runs in the
       browser; no backend.
    2. main.py + src/ - a Python 3.11 desktop webcam preview (OpenCV window)
       that overlays MediaPipe Pose Landmarker ankle/heel/toe landmarks.

What can be demonstrated today
  - Web app (desktop Chromium, verified in this audit with a simulated camera):
    Start Camera -> live preview -> Scan Foot -> tap -> real model inference in
    a Web Worker -> green candidate overlay on the frozen frame -> Retry ->
    second scan -> Stop Camera releases the stream. A denied camera permission
    shows the correct guidance message.
  - Catalog (verified in desktop Chromium, touch emulation and the production
    build): 15 cards, one per product with local photos, 72 photos. Swipe,
    arrows and keyboard all work, and each card keeps its own photo. No
    horizontal overflow from 320 px to 1440 px.
  - 3D View (Step 3A): the first card (2649-bka LEOHARDT LOAFER) has a 3D slide
    after its 5 photos. It shows a procedural GLB of the right shoe that rotates
    by drag, with Reset view and a photo fallback. Verified in desktop and
    mobile-viewport Chromium, on the dev server and the production build.
  - Real-model smoke test page passes (model + WASM runtime integration).
  - Python: real pose model loads and runs inference headlessly; 19 unit tests
    pass.
  - All automated checks pass: frontend typecheck, lint, 75 tests, production
    build; Python 19 tests and pip dependency check.

What blocks completion
  - No shoe try-on exists. The catalog shows 15 of 246 LOGO Formal products,
    because only 15 have local photos. Foot pose/scale estimation for placement
    and shoe rendering are missing. Each card says "Virtual try-on coming soon".
  - Reuse permission for the LOGO photos is UNVERIFIED (public_reuse_status
    is "unverified" on all 72). Deploying the site publicly, including the
    Vercel Git deployment from main, would publish them. Confirm permission
    first (TASK-017).
  - The product scope is undocumented beyond the current step. The README
    calls the web app "Step 5", but no roadmap or requirements document
    exists in the repo. Which track (web or Python) is the product path is
    not stated.
  - The segmenter is a general-object model. It cannot tell whether a foot is
    present, which the docs also state. Real-foot accuracy and real phone
    behavior have not been verified in any recorded check.

Three most important next steps
  1. TASK-001: Owner decides and documents the MVP scope: what "try-on" means,
     web vs Python, target devices, and shoe asset source. Everything after
     step 2 depends on it.
  2. TASK-002: Verify the current web prototype on a real Android phone and an
     iPhone over HTTPS, using the checklist in frontend/README.md. Record scan
     latency, because about 14-17 s per scan was observed in headless desktop
     Chromium.
  3. TASK-017 before any public deploy of the catalog. Then TASK-005..007:
     build the first end-to-end try-on on a captured snapshot. Derive the foot
     axis and scale from the mask, then render the selected catalog shoe
     (stable ID = dataset slug) aligned to the foot.

Main data flows
  Catalog flow (build time + browser):
    vite/logoFormalCatalog.ts reads data/logo-formal/products.json ->
    normalizeCatalog(): keeps slugs with >= 1 local photo that exists under
    data/logo-formal/images/ and matches its sha256; orders main first, then
    gallery_position; dedupes by path/hash; converts description HTML to text
    paragraphs -> emits a module that imports each original JPG (Vite fingerprints
    them into dist/assets/; dev serves them via server.fs.allow limited to the
    images folder) -> CatalogPage renders one ProductCard per product.
  Web scan flow (/scan/):
    Start Camera -> useCamera.start(): isSecureContext and API check ->
    getUserMedia({video: environment, 1280x720 ideal, audio:false}) -> <video>.
    Scan Foot -> useFootScan.retry() sets phase "selecting" -> FootSelection
    overlay -> pointerup/Enter -> geometry.mapTap (object-fit contain, rejects
    letterbox) -> drawImage of current video frame to canvas (<=768 px) ->
    getImageData -> SegmentationClient.segment(): Worker (module) +
    OffscreenCanvas available ? postMessage with transferred pixels :
    main-thread engine fallback -> engine.createEngine loads
    /segmentation/wasm + /segmentation/interactive_segmentation.task (CPU) ->
    InteractiveSegmenter.segment(point) -> Float32 confidence mask ->
    mask.colorMask threshold 0.5 + warnings -> putImageData onto the frozen
    canvas -> phase "result". Stop/pagehide/hidden/unmount -> cancel(), which
    disposes the worker and discards late results.
  Python flow:
    main.py -> FootTracker(model) -> run_camera_preview(index, processor) ->
    each frame: BGR->RGB -> PoseLandmarker.detect_for_video (monotonic ms) ->
    extract_foot_landmarks (filters) -> mirrored preview + draw -> imshow;
    Q/Esc exits; camera and model are released in finally / context manager.

Environment variables
  None are required by either application. The code reads no custom env
  vars; only Vite's built-in import.meta.env.BASE_URL is used.
  MPLCONFIGDIR (optional, Python tests only) - points matplotlib's cache into
  .venv to avoid writing elsewhere; the README sets it.
  .gitignore reserves frontend/.env.local, but nothing uses it today.
